# 기획서 보완점 (Novel Story)

`기획서.txt` 검토 결과, 뼈대는 잘 잡혀 있지만 실제 구현 전에 짚고 넘어가야 할 공백들을 우선순위별로 정리합니다.

## 1. 핵심 기능 누락 (가장 먼저 채워야 할 부분)
- **게시글 작성/수정 페이지가 없음**: 목록·상세 화면 명세는 있는데, 글을 쓰는 화면 자체가 기획서에 빠져있음. 제목/내용/소설·잡지 제목 입력 폼, 이미지 첨부 여부 등을 정의해야 함
- **"소설/잡지 평점" 기능이 특별 기능에는 있는데, 게시물 목록/상세 명세에는 UI가 안 보임**: 이 둘을 연결해서 어디서 몇 점을 어떻게 매기는지 구체화 필요
- **댓글/게시글 수정·삭제 기능이 없음**: 좋아요·대댓글은 있는데 정작 본인 글/댓글 수정·삭제는 빠져있음

## 2. 데이터 구조 관점에서 재검토가 필요한 부분
가장 중요한 지점. 지금 구조는 "게시글 = 소설/잡지 제목을 자유 텍스트로 적는 형태"로 보이는데, 이러면 문제가 생김.

- 같은 소설(예: "달러구트 꿈 백화점")을 다루는 게시글이 여러 개 있을 때, "이 소설의 평점"을 어디에 저장할지 애매함. 게시글마다 평점을 매기면 "소설 자체의 평균 평점"이 아니라 "게시글 평점"이 되어버림
- **제안**: `소설/잡지` 마스터 테이블을 따로 만들고(제목, 작가/출판사, 장르, 표지 이미지 등), 게시글은 그 소설을 참조(FK)하는 구조로 설계. 이러면 "소설별 평균 평점", "이 소설을 다룬 글 모아보기" 같은 기능도 자연스럽게 나옴
- 게시글 작성 시 소설 제목을 자유 입력할지, 기존 등록된 소설 중에서 선택(검색 후 없으면 새로 등록)하게 할지 결정 필요

## 3. 회원가입/로그인 관련
- **전화번호 수집 목적이 불명확**: 본인인증(SMS 인증)용인가, 아니면 그냥 프로필 정보인가? 실제 인증 없이 텍스트로만 받는다면 굳이 필요한 개인정보인지 재고 필요. 불필요한 개인정보 수집은 이용자 부담도 크고, 나중에 개인정보처리방침 작성 시 부담이 됨
- 이메일 인증(가입 확인 메일) 절차가 없음 — Supabase Auth를 쓰면 기본 제공되는 기능이라 설정만 하면 됨
- 닉네임 중복 확인 로직 필요
- "비밀번호 찾기" 버튼은 있는데, 실제 흐름(이메일로 재설정 링크 발송 → 새 비밀번호 입력 페이지)이 명세에 없음
- 비밀번호 정책(최소 길이 등) 기준이 없음
- **회원 탈퇴, 프로필 수정 페이지가 아예 빠져있음**

## 4. 커뮤니티 운영에 꼭 필요한데 빠진 것들
- **게시글/댓글 신고 기능**이 없음: 커뮤니티는 운영이 시작되는 순간 악성 게시글·도배·저작권 문제가 생기기 마련이라 최소한의 신고 버튼은 필요
- **관리자 페이지**가 없음: 신고 처리, 회원 관리, 게시글 강제 삭제 등을 할 수단이 없으면 운영이 불가능
- **검색 기능**이 없음: "소설/잡지 정보 공유"가 주제인 만큼 소설 제목/작성자로 검색하는 기능은 사실상 필수
- **정렬 옵션**(최신순/인기순/평점순)도 목록 화면에 명시가 안 되어 있음
- 이용약관 / 개인정보처리방침 페이지 — 특히 전화번호 같은 개인정보를 수집한다면 법적으로 필요

## 5. 세부 UX 디테일
- **좋아요 토글 여부**: 한 번 누른 좋아요를 다시 눌러 취소할 수 있는지, 같은 유저가 중복으로 누를 수 없도록 막을지(DB에서 unique 제약 필요) 명세 필요
- **대댓글 depth 제한**: 대댓글에 또 대댓글이 가능한지(무한 depth) 아니면 1단계로 제한할지 정해야 UI/DB 설계가 편함
- **알림 기능**: 내 글에 댓글이나 좋아요가 달렸을 때 알림이 없으면 재방문 동기가 약해짐. MVP에서는 빼더라도 "추후 확장 아이디어"로 남겨두는 것을 추천
- **마이페이지**: 내가 쓴 글/댓글, 좋아요한 글, 평점 히스토리를 모아보는 페이지가 없음
- 목록 화면의 **페이지네이션/무한스크롤** 방식이 정해져 있지 않음

## 6. 디자인 명세 보완
- "파스텔톤의 푸른색"은 Primary 컬러로 좋은데, Secondary/Accent 컬러, 폰트 컨셉이 없음
- 참고 사이트로 "네이버 카페", "교보문고"를 적었는데, **구체적으로 어떤 요소를 참고할지**가 없음. 예를 들어 "네이버 카페의 게시판 카테고리 구조", "교보문고의 도서 정보 카드 UI" 처럼 명시하면 실제 디자인 작업 때 훨씬 도움이 됨

---

## 우선순위 제안
MVP로 먼저 구현할 거라면 **2번(데이터 구조)**, **1번(게시글 작성 페이지)** 부터 확정하고, **4번(신고 기능)**은 최소한만이라도 넣는 것을 권장. 3·5·6번은 기획서에 "추후 개선" 항목으로 남겨두고 진행해도 무방함.
