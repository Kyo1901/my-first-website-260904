03

데이터 모델 개요

게시글마다 소설/잡지 제목을 자유 텍스트로 받지 않고, 마스터 데이터로 분리해 참조한다.

소설/잡지를 별도 테이블로 관리하면 소설별 평균 평점과 같은 책을 다룬 글 모아보기가 자연스럽게 구현된다. 게시글 작성 시에는 소설/잡지를 검색 후 선택하고, 목록에 없으면 그 자리에서 새로 등록한다. 실제 컬럼·제약 조건은 7장 DB 구조 상세에서 다룬다.
소설/잡지 마스터
  • 제목 · 작가/출판사
  • 장르 · 표지 이미지
  • 평균 평점(집계)
게시글
  • 제목 · 본문 · 작성일
  • 작성자(FK)
  • 소설/잡지(FK)
  • 좋아요 수
→ 소설/잡지를 참조
댓글
  • 내용 · 작성 시간
  • 작성자(FK)
  • 상위 댓글(FK, 대댓글)
→ 게시글을 참조 · 자기 자신 참조(대댓글)
평점
  • 점수(5점 만점)
  • 작성자(FK)
  • 유저 × 소설 유니크
→ 소설/잡지를 참조
좋아요
  • 작성자(FK)
  • 대상 종류(게시글/댓글)
  • 유저 × 대상 유니크, 토글
→ 게시글 또는 댓글을 참조
신고
  • 신고자(FK) · 사유
  • 대상 종류(게시글/댓글)
  • 처리 상태
→ 게시글 또는 댓글을 참조
04

페이지별 기능 명세

회원가입부터 관리자 화면까지, 총 10개 화면의 기능을 정의한다.

4.1

회원가입 페이지

  • 이메일(계정) — 중복 검사만으로 즉시 가입
  • 비밀번호(8자 이상 권장) · 비밀번호 확인
  • 닉네임(중복 확인)
  • 회원가입 버튼
전화번호는 수집 항목에서 제외
4.2

로그인 페이지

  • 이메일 · 비밀번호 입력
  • 로그인 / 회원가입 버튼
  • 비밀번호 찾기 → 재설정 링크 발송 → 새 비밀번호 입력
4.3

게시물 목록 페이지

  • 검색(소설/잡지 제목, 작성자)
  • 정렬(최신순 · 인기순 · 평점순)
  • 게시글 카드 · 최근 댓글 2개 미리보기
  • 페이지네이션
4.4

게시글 작성/수정 페이지

  • 소설/잡지 검색 후 선택(없으면 신규 등록)
  • 제목 · 본문 · 이미지 첨부(선택)
  • 본인 글에 한해 수정·삭제
4.5

게시물 상세 페이지

  • 본문 · 연결된 소설/잡지 정보 + 평균 평점
  • 좋아요 버튼(토글) · 신고 버튼
  • 본인 글 수정·삭제, 댓글 영역
4.6

댓글 기능

  • 댓글 좋아요(토글)
  • 대댓글(1단계까지)
  • 본인 댓글 수정·삭제 · 신고
4.7

소설/잡지 평점 기능

  • 별점(5점 만점) 등록
  • 유저당 소설 1개에 평점 1회(재평가 시 수정)
  • 목록/상세에 평균 평점 노출
4.8

마이페이지

  • 내가 쓴 글 · 댓글 · 좋아요한 글
  • 내 평점 히스토리
  • 프로필 수정 · 회원 탈퇴
4.9

관리자 페이지

  • 신고 목록 확인 및 처리
  • 회원 제재/탈퇴 처리
  • 소설/잡지 마스터 데이터 정리
4.10

정책 페이지

  • 이용약관
  • 개인정보처리방침(이메일 · 닉네임 · 비밀번호)

07

DB 구조 상세

3장의 데이터 모델을 Supabase(Postgres) 기준 실제 테이블로 설계한다. 모든 테이블명은 ns_로 시작한다.

설계 원칙
·테이블명 접두사 — 모든 테이블은 ns_로 시작해 다른 서비스와 네임스페이스가 섞이지 않도록 한다.
·기본 키 — uuid default gen_random_uuid(). Supabase Auth의 auth.users.id와 타입을 맞춘다.
·회원 정보 — 이메일·비밀번호는 auth.users가 관리하고, ns_profiles는 닉네임 등 앱 전용 정보만 갖는 1:1 확장 테이블이다. 전화번호 컬럼은 두지 않는다.
·대상 분리 — "게시글 또는 댓글"을 함께 대상으로 하는 좋아요·신고는 폴리모픽 컬럼 대신 대상별로 테이블을 분리해 실제 FK·UNIQUE 제약을 건다.
·집계 캐싱 — 좋아요 수·댓글 수·평균 평점은 컬럼으로 캐싱하고 트리거로 동기화해 매 요청마다 COUNT 쿼리를 돌리지 않는다.
